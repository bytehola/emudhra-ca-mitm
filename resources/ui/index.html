使用方法

仅用于自有或已获授权的测试设备和应用。

Frida 注入
  1. 界面显示 Frida 不可用时，先在当前 Python 环境安装 frida-tools 14 或更高版本。
  2. Android 开启 USB 调试，并确认设备已连接。
  3. 点击“启动 Frida 与代理”会启动代理、应用设备系统代理并自动检测 root；有 root 时下载并启动匹配版本的 frida-server。
  4. 无 root 时仅对可调试 App 自动准备 Gadget；不可调试 App 仍需重打包注入 Gadget。
  5. MuMu、LDPlayer 等 x86_64 Native Bridge 环境运行 arm64 App 时，Frida Spawn 会触发 SIGSEGV，请改用 ARM64 原生模拟器或 ARM64 真机。
  6. App 会被重新拉起；脚本安装完成后重新操作目标功能。
系统 CA

将当前 CA 根证书安装到 Android 系统信任库，通常需要 root、Magisk 系统证书模块或可写系统分区。

Android 7 及以上版本默认不信任用户证书；仅安装用户 CA 通常无法解决 App 的 certificate unknown。

Reqable SSL Bypass

可在支持 root 或模拟器的环境使用 Reqable 的 SSL Bypass。它适合作为 Frida 之外的验证方式，但不能覆盖所有加固和原生 pinning。

Network Security Config

仅对自有测试包或允许重打包的 App 使用。为 debug 构建配置用户 CA 信任，或调整证书校验逻辑后再签名安装。

无线 ADB

Android 11 及以上在“无线调试”中分别查看设备地址和配对地址。先填写设备地址，再用配对地址和 6 位配对码执行“配对并连接”。

已通过 USB 执行过 adb tcpip 5555 的设备，或已开启无线调试的设备，也可直接填写 IP:端口 后点击“连接”。

ADB 系统代理

“启动并应用代理”只启动本工具代理，并为所选设备执行 adb reverse 和设置 Android 全局 HTTP 代理；不会启动目标 App。

通过 ADB 自动应用时，设备端使用 127.0.0.1:28081，由 adb reverse 转发到电脑。若在局域网设备上手动填写 Wi-Fi 代理，127.0.0.1 指设备自身，必须改为电脑局域网 IP，例如 192.168.1.10:28081。

停止代理或关闭本工具时会恢复设备原代理。设备异常断开时，应重新连接后点击“恢复代理”。

Native Pinning

Flutter、BoringSSL、自研 native 网络库或加固壳可能绕过 Java TrustManager。此时需要 native hook、魔改库或针对目标二进制的专用方案。
